# Ocean Tap

海の中を眺めて、タップで干渉する、iPhone の Safari 向けの小さなゲームです。
魚の群れが泳ぐのをぼんやり眺めたり、触ってちょっかいを出したりして遊びます。

**公開URL：https://niko12-coder.github.io/ocean-tap/**

（GitHub Pages に反映されるまで、公開から数分かかることがあります。404 のときは少し待ってから開き直してください）

## 遊び方

| 操作 | 起きること |
|---|---|
| タップ | その場所に波紋が広がり、近くの魚が驚いて逃げる（遠い魚ほど遅れて驚く）。近くの泡は、波紋の輪が届いた瞬間に「パチン」と弾ける（半径30pt の内側は全部、そのすぐ外は半分、120pt に向けて1割まで減っていく。自動で浮かぶ泡も含む） |
| 長押し（0.2秒〜） | 指の周り（半径16px）に茶色〜オレンジの小さなエサが散らばって沈む。押し続けるほど少しずつ量が増える。魚がゆっくり集まって食べる。押している間に指が18px以内しか動かなければ、長押しのまま |
| 指でなぞる | 軌跡に泡が出る。指の近くの魚はそっと避ける。なぞった泡の列は、魚が壁のように避けて泳ぐ。泡の半分は、魚に触れると「パチン」と弾けて、魚はビクッと離れる。残りの半分は弾けずに魚を押し返す（タップで出る泡も同じ。自動で浮かんでくる泡は関係しない） |
| 右上の歯車 | 設定パネルが下から出る。もう一度タップするか、パネルの外をタップするか、上のバーを下へスワイプすると閉じる |

何もしなくても、群れは画面の中をゆっくり泳ぎ回ります。

### 設定パネル

開いてすぐ見えるのは「魚の数」「テーマ」「省電力」だけです。ほかの項目は「詳細設定」を開くと出てきます（中は3つのタブ）。変更はすぐ画面に反映されます。設定はこの端末のブラウザ（localStorage）に保存され、次に開いたときも復元されます。パネルを触っている間の操作は、ゲーム側（波紋・泡・エサ）には伝わりません。

上のバーを下へスワイプすると、指に合わせてパネルが下がります。ある程度（高さの3割か110px の小さいほう）下げて離すか、素早く下へはじくと閉じ、足りなければ元に戻ります。

| タブ | 項目 |
|---|---|
| 基本（常に表示） | 魚の数（初期値 100）、テーマ（初期値 深海）、省電力（30fps。初期値 OFF） |
| 詳細設定 → 魚 | 泳ぐ速さ、逃げる強さ、エサへの集まりやすさ、エサの量、エサの大きさ |
| 詳細設定 → 泡・粒子 | なぞった時の泡の量、泡の上限数、漂う粒子の数、光の筋の強さ |
| 詳細設定 → 背景 | 海底の飾り（岩・海藻・サンゴ）のON/OFF |

テーマは、標準・浅瀬・深海・夕方の海・サンゴ礁の5つです。「初期値に戻す」（詳細設定の一番下）で、すべての設定を初期値に戻せます。

テーマを切り替えると、色が1.6秒ほどかけて移り変わります。深海では粒子がほのかに光り、夕方の海では光の筋が暖色になります。

「省電力」をONにすると、1秒に30回だけ動かして描きます（ふだんは60回）。動きは少し粗くなりますが、電池と発熱が半分ほどになります。iPhone の低電力モード中は、ONにしなくても Safari が30回に抑えます。

### ホーム画面に追加して全画面で遊ぶ

1. iPhone の Safari で上のURLを開く
2. 共有ボタン →「ホーム画面に追加」
3. ホーム画面のアイコンから起動すると、Safari の枠なしで全画面になる

## 改造のヒント

`index.html` の中は、番号つきの見出しコメントで区切ってあります。

1. 設定（`CONFIG`・魚の群れの定義・背景テーマ `THEMES`・設定パネルの項目 `SCHEMA`）
2. 道具（乱数など）と、保存される設定
3. キャンバスと画面サイズ
4. あらかじめ描いておく絵（光の筋・泡・粒の光）
   - 4b. 背景（テーマごとの水の色・砂丘・岩・サンゴ、色の移り変わり）
5. 登場する物のデータ（魚・泡・粒・海藻）
6. 操作（タップ・長押し・なぞる）
7. タップの波紋と、魚の驚き
8. 毎フレームの更新（魚の動き・エサ・泡・粒）
9. 描画（奥から手前の順）
10. メインループと自動品質調整
11. 設定パネル
12. 起動

まず触るとよいのは、最初の `CONFIG` です。パネルで変えられる項目の「初期値」もここにあります。

- 魚の数：`FISH_COUNT`（既定 100）。重いなら 30〜60 に。重い端末では自動調整が減らす
- テーマの初期値：`THEME`（既定 `'deep'`）
- 長押し・なぞり：`LONG_PRESS_MS`（長押しと判定する時間。既定 200）・`MOVE_THRESHOLD`（これ以上動くと「なぞる」。既定 18px）
- 泡の上限：`BUBBLE_LIMIT`（既定 400）、パネルで上げられる最大は `BUBBLE_LIMIT_MAX`（400）
- 群れの動き：`SEPARATION_W`（分離）・`ALIGNMENT_W`（整列）・`COHESION_W`（結合）
- 驚きやすさ：`SCARE_RADIUS`・`FLEE_SPEED`・`PANIC_TIME`
- タップの衝撃：`SHOCK_R`（泡が弾ける範囲）・`SHOCK_SURE_R`（必ず弾ける範囲）・`SHOCK_NEAR_CHANCE` / `SHOCK_EDGE_CHANCE`（その外側のすぐ近くと、範囲の縁で弾ける割合）
- 泡と魚：`BUBBLE_HIT_R`（魚の当たりの大きさ）・`BUBBLE_POP_CHANCE`（触れたら弾ける泡の割合）・`BUBBLE_WALL_MAX`（壁の力の上限）・`BUBBLE_FLINCH` / `BUBBLE_PANIC`（ビクッとする強さ）・`BUBBLE_WALL_R` / `BUBBLE_WALL_W`（泡の壁に気づく距離と避ける力）・`POP_LIFE`（パチンの表示秒数）
- エサ：`FEED_RATE_START` / `FEED_RATE_END` / `FEED_RAMP_SEC`（落とす量と、押し続けたときの増え方）・`FOOD_SPREAD_R`（散らばる半径）・`FOOD_SIZE`（粒の大きさ）・`FOOD_COLORS`（粒の色）・`MAX_FOOD`（上限）・`FOOD_W`（集まる速さ）
- 魚の色や大きさ：`SCHOOL_DEFS`（群れごとの色・大きさ・泳ぐ深さ・割合）

魚の姿は `drawFish()`、群れの動きは `updateFish()` にあります。

### テーマを足す

`THEMES` に1つ書き足すだけで、パネルの選択肢にも出ます。水の色（`sea`）、砂丘・岩・サンゴの色、霞み、粒子、光の筋、海藻の色を決めます。書き方は `THEMES` の上のコメントにあります。

### パネルの項目を足す・変える

`SCHEMA` の1行が、パネルの1項目（スライダー・テーマ選択・スイッチ）に対応しています。`basic: true` を付けた項目は開いてすぐの場所に、付けない項目は「詳細設定」の中のタブに出ます。項目を足すと、保存・復元・初期値に戻す、も自動で効きます。足した項目を実際に反映するには、`applySetting()` に1行足すか、毎フレーム `settings.キー名` を読む処理を書きます。

### 初期値を変えたとき（保存データのバージョン）

保存データには番号（`SETTINGS_VERSION`）が入っています。`CONFIG` や `SCHEMA` の初期値を変えたら、この番号を1つ上げてください。古い番号で保存されたデータは捨てられ、新しい初期値で始まります（上げ忘れると、以前に開いた端末には古い設定が残ります）。

### 調べるときのURLオプション

| 付け方 | 効果 |
|---|---|
| `?fish=30` | 魚の数を一時的に変える（保存済みの設定より優先。端末ごとの調整に） |
| `?fps` | 左上に fps・1コマの処理時間（work。GPU で塗る時間は入らない目安）・描画の細かさ（dpr）・魚の数・泡の数を表示する。fps と work は約1.5秒ごとの平均で、最初の計測が終わるまでは `--`。自動調整で光の筋を止めているときは `rays off`、低電力モードの30fps固定と判断したときは `30fps cap` が出る |
| `?debug` | ブラウザのコンソールから `window.__ocean` で中身を覗ける |

## 軽さについて

- 描画は Canvas 2D だけ。背景・奥と手前の海底の飾り・光の筋・泡の絵は、起動時やテーマ切り替え時に1回だけ作って使い回す。テーマの切り替えが終わったら、前のテーマの絵は捨ててメモリを返す
- 光の筋は、画面の1/4の粗さ（`RAY_SCALE`）の裏キャンバスに描いて、1枚で引き伸ばして重ねる。光の筋はぼやけた絵なので見た目はほぼ変わらず、描画の時間は半分以下になる（以前は描画のほとんどを光の筋が占めていた）
- 泡の絵は 64・32・16・8px の4サイズを起動時に作り、描く大きさに近いものを使う（大きな絵を数pxへ一気に縮めると、輪郭の線が点線のように途切れるため）
- 泡は上限（既定400）に達したら、いちばん古い泡から作り直して使い続ける。泡の入れ物は使い回す（プール）ので、なぞり続けても新しい確保がほとんど起きない
- エサも泡と同じ方式。上限（既定300）に達したら古い粒から作り直し、食べられた・消えた粒は使い回す。描画は色ごとにまとめて塗る
- 画面の細かさ（devicePixelRatio）は `MAX_DPR`（既定 2）まで。3 にするとさらに高精細だが重くなる
- 魚の群れの計算は、同じ群れの中だけで行う
- タップの衝撃は、タップした瞬間に1回だけ、近くの泡に「輪が届く時刻」を予約する（毎フレームの計算は増えない）
- 泡と魚の当たりは、毎フレーム、ユーザーの泡を画面のマス目に振り分けて、魚は自分の周りのマスの泡だけを調べる（泡400×魚100を総当たりすると4万回になるのを、数百回に抑える）
- `AUTO_QUALITY` が `true` のとき、目標の約75%（60fps なら45、省電力の30fps なら22.5）を下回ると、見た目が変わりにくい順に1段ずつ軽くする
  1. 描画の細かさ（DPR）を `AUTO_DPR`（1.5）へ下げる。輪郭が少し柔らかくなるだけで、描く量は約4割減る
  2. 光の筋を止める
  3. 魚を1割ずつ減らす（`MIN_FISH_COUNT` まで。パネルのスライダーはそのままで、「100匹（いまは80匹）」のように実際の数が出る）

  どれもその回だけで保存しない。開き直すと元に戻る。パネルで魚の数や光の筋の強さを動かすと、その項目は自動で下げた分が解除される。テーマの色が移り変わっている途中は、1は終わるまで待つ。
- 60fps を狙っているのに30fps前後のときは、iPhone の低電力モード（Safari が30fpsに固定）か、端末の力が足りず1コマおきにしか描けていないのかを、fps の数字（どちらも約33ms間隔）でも JavaScript の処理時間（GPU で塗る時間が入らない）でも見分けられない。そこで1か2を試しに1段だけ下げ、次の計測で30fps前後から抜けたら力不足とみなしてそのまま続ける。抜けなければ低電力モードとみなして元に戻し、`CAP_RETRY_SEC`（30秒）は試さない。この帯では魚は減らさない

## ローカルで動かす

`index.html` をブラウザで開くだけで動きます。サーバーを立てる場合は、次のとおり。

```bash
python -m http.server 8000
```

その後 http://localhost:8000/ を開きます。
